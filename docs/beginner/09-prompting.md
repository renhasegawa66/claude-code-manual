# 9. プロンプトの作法

<div class="section-quote">
「<strong>プロンプトとは、理想と現実のギャップを埋めるもの。それ以上でも以下でもない</strong>」<br>— 薄井 匠
</div>

## 大前提 — "プロンプト集" は学ばなくていい

- 「あなたはプロの〇〇です」のような **役割プロンプトは現代では不要**
- 他人のプロンプト集をコピペするより、**自分の理想を言語化** することが本質
- 役割は最低限あれば良い（"道草のブランドマネージャとして" 程度）

## 4 つの基本作法

### 1. 解像度が低い領域は AskUserQuestion に逆質問させる

```text
タスク管理アプリを作ってください。
要件が曖昧な箇所があれば、AskUserQuestion ツールで
私に逆質問してください。
```

→ Claude 側から「Web か、ネイティブか？」「ログインは必要か？」と聞いてきて、
**最初の解像度を上げてくれる**。

### 2. 大規模は Plan モード経由で

- 重いタスクは **計画を見てから実行**
- 「思っていた方向と違う」を最初の段階で止める
- 詳細は [3. 5 つの権限モード](/beginner/03-permissions)

### 3. 命名規則を指定する

```text
領収書ファイルを、
"YYYYMMDD_クライアント名（会社名）_但し書き.jpg"
の形式に統一してください。
```

**フォーマットを与えると後工程が圧倒的に楽** になります。

### 4. 出力フォーマットを指定する

```text
最終出力は次の形式でお願いします:
- 表ではなくプレーンテキスト
- 1 行目: タイトル
- 2 行目以降: 箇条書き
- 末尾に "完了" と書く
```

## 音声入力を活用する

::: tip 講師の推奨
**寿司打 全国 12 位** のタイピング速度でも、**音声入力の方が早い** と講師は断言。
- ツール: Aqua Voice / TypeRess / Voice OS / OS 標準
- どれでも OK
- 「人間に話しかける」ではなく **「機械に話しかける」** ことに慣れる
:::

音声入力前提で書く場合は、**多少の誤字脱字は許容して構いません**。
Claude Code は文脈で補正してくれます。

## "出戻り" を最小化する

Claude Code は **1 時間平気で作業し続けます**。
そのため、**最初のスペックの解像度が低い** と、
1 時間まるごと無駄になる事故が起きます。

> 「タイトなリソースでクイックなローンチを目指す
>   バイブコーディング AI スタートアップでのベストプラクティスは、
>   **最初のプロンプト時点でのスペックの解像度**」
> — *薄井氏が "ひいおばあちゃん" に教わったとされる金言*

## セッションを節約するテク

- 要件定義の壁打ちは **ChatGPT / Gemini で済ませる**
- 固まったら、まとまった仕様を Claude Code に渡す

これで Claude Code のコンテキストとクレジットを節約できます。

## 5 つのチェックリスト

依頼を送る前に、以下を口に出して確認：

- [ ] **アウトプットの形** は具体的に書いたか？（ファイル？テキスト？フォーマット？）
- [ ] **保存場所** を指定したか？（フルパス推奨）
- [ ] **大規模なら Plan モード** を選んでいるか？
- [ ] **解像度が低ければ AskUserQuestion** を許可しているか？
- [ ] **送信や公開などの不可逆操作** を含む場合、**禁止** を明示したか？
