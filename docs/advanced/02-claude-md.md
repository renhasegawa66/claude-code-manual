# 2. CLAUDE.md 設計術

## CLAUDE.md とは

`CLAUDE.md` は、Claude Code が **毎回読み込む "服に書かれたメモ"** です。
あなたの好み・前提・禁止事項を書いておくと、それを踏まえて動いてくれます。

| 種類 | 場所 | 適用範囲 |
| --- | --- | --- |
| **グローバル** | `~/.claude/CLAUDE.md` | すべての作業に適用 |
| **プロジェクト** | `<project>/CLAUDE.md` | その案件のみ |

## 編集する一番速い方法

`/init` などのコマンドもありますが、講師曰く **自然言語が一番速い**：

```text
グローバル CLAUDE.md に
"Web サイトを作ったら Playwright MCP で動作確認する"
というルールを追加してください。
既存ルールと矛盾しないように。
```

## 過信は禁物

::: tip 講師の本音
「`CLAUDE.md` は本当に大事、と書いている記事が多い。
でも僕は実は **過信していない**。
最強プロンプト集を集めまくる行為に近い。
**本当に効くものだけ書く**」
:::

## 講師の実例（要点）

実際に薄井氏のグローバル `CLAUDE.md` に入っているルールの抜粋：

| ルール | 意図 |
| --- | --- |
| すべての発話を関西弁にする | エンタメ用（笑） |
| 音声入力前提なので誤字脱字は文脈で補正する | 入力作法 |
| 大きめのタスクはチームエージェントで分割する | 並列実行を促す |
| ファイル生成時は **必ずフルパスを最後に明記** する | 探す手間を消す |
| 文字起こしは Whisper ではなく **MLX Whisper** を使う | Apple Silicon で 約 30× 高速 |
| Web サイト／アプリを作ったら **Playwright MCP で動作テスト** | 完成宣言の前の検証 |
| 新規プロジェクトは `~/dev-projects/<名前>/` に作る | 散らかり防止 |
| プロジェクトで作ったら GitHub にも push する流れまで進める | ワークフロー固定 |

## CLAUDE.md に書くべきこと（推奨カテゴリ）

### 1. 立ち振る舞いルール
- 並列処理を使う／使わない
- 音声入力前提か
- 完成前に必ずやるべき検証（Playwright など）

### 2. 出力フォーマット
- ファイルを作ったらフルパスを明記する
- レポートの章立てを統一する
- 日付は YYYY-MM-DD で書く

### 3. プロジェクト場所のルール
- `~/dev-projects/<name>` に作る
- Desktop に作るのは明示指示があったとき

### 4. GitHub / デプロイ運用
- デフォルトのリポジトリ公開設定（public / private）
- 命名規則
- `.gitignore` に必ず入れるファイル

### 5. セキュリティ
- API キーは `.env` で扱う
- 機密データはコミットしない
- メールは送信せず下書きまで

## 原始人プロンプト（Caveman Prompt）

海外で流行している **トークン節約 TIPS** です。

```text
[原始人プロンプト]
原始人として振る舞う。
単語ベースで話す。敬語禁止。単文完結。
ただし技術説明は省かない。
```

これを CLAUDE.md に入れると、Claude の出力が
**「了解。シンプルアラーム作る。フォルダはどこ？ GitHub push 進める」**
のような短文に切り替わります。

::: warning 副作用
読みづらくなるので、**本気でトークン節約したい人向け**。
講師の言葉では「Claude が "俺、人間殺す" みたいな喋り方になったら成功」。
:::

## CLAUDE.md のテンプレート

::: code-group
```markdown [推奨テンプレ]
# 立ち振る舞いルール

## プロジェクト場所
- 新規プロジェクトは `~/dev-projects/<name>/` に作る
- Desktop に作るのは明示指示があったときのみ

## 完成の定義
- Web アプリを作ったら **必ず Playwright MCP で動作確認** してから完成と言う
- 静的解析（型・lint）だけで完了扱いにしない

## 並列処理
- 大きいタスク・調査は **チームエージェント** を編成して並列で進める
- 1 ファイル参照・1 キーワード grep は対象外

## セキュリティ
- API キーはハードコードしない。`.env` を使い `.gitignore` に追加
- 公開デプロイ前に **必ず Supabase RLS を確認**
- メール MCP は **下書きまで**

## 出力フォーマット
- ファイル生成時は最後にフルパスを箇条書きで明示
- 日付は YYYY-MM-DD
- 完了報告は「変更点 1 行 + 次の一手 1 行」

## 音声入力
- ユーザは音声入力。誤字脱字は文脈で補正してから処理
```
:::

## CLAUDE.md デバッグの仕方

書いたルールが効いていないと感じたら：

```text
今、適用されている CLAUDE.md のルールを
箇条書きで全部列挙してください。
読まれていないものがあれば教えてください。
```

→ Claude が **実際に認識しているルールセット** を返してくれます。
