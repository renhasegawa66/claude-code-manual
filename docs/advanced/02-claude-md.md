# 2. CLAUDE.md 設計術

## CLAUDE.md とは

<figure class="slide-figure">
  <img src="/slides/advanced/page-016.jpg" alt="Claude Code のディレクトリ構造と CLAUDE.md">
  <figcaption>CLAUDE.md は Claude が必ず従う「ルールブック」（p.16）</figcaption>
</figure>

`CLAUDE.md` は、Claude Code が **毎回読み込む "服に書かれたメモ"** です。
あなたの好み・前提・禁止事項を書いておくと、それを踏まえて動いてくれます。

| 種類 | 場所 | 適用範囲 |
| --- | --- | --- |
| **グローバル** | `~/.claude/CLAUDE.md` | すべての作業に適用 |
| **プロジェクト** | `<project>/CLAUDE.md` | その案件のみ |

## 比喩：『博士の愛した数式』

<figure class="slide-figure">
  <img src="/slides/advanced/page-021.jpg" alt="博士の服についたメモ">
  <figcaption>博士の服に書かれた「自分は記憶喪失」のメモが CLAUDE.md のイメージ（p.21）</figcaption>
</figure>

> 「天才数学者の博士は 90 分以上記憶が持たないため、
> **毎朝服についたメモを読んで自分が誰かを理解することから始める**。
> このメモが `CLAUDE.md` のイメージ。
> Claude Code は起動するたびにこれを読み込む」 — 薄井 匠

メモには例えばこう書かれている：
- 自分は記憶喪失
- 記憶は 90 分のみもつ
- 家政婦の鈴木さんが朝 10 時にやってくる
- 鈴木さんの子供はルート君

CLAUDE.md も同じ役割。Claude Code に **「あなたはこういうルールで動くエージェントだ」** を毎朝教える紙です。

## 編集する一番速い方法

`/init` でも雛形は作れますが、講師曰く **自然言語が一番速い**：

```text
グローバル CLAUDE.md に
"Web サイトを作ったら Playwright MCP で動作確認する"
というルールを追加してください。
既存ルールと矛盾しないように。
```

## 過信は禁物

::: tip 講師の本音
> 「SNS では『生産性を上げる最強の CLAUDE.md』みたいな投稿が散見するが…
> 個人的には、正直そこまで気にする必要はないと思っている」（p.23）

最強プロンプト集を集めまくる行為に近い。**本当に効くものだけ書く** のがコツ。
:::

## 講師の実例（要点）

スライド原文（p.23-24）から、薄井氏のグローバル `CLAUDE.md` に入っているルール例：

| ルール | 意図 |
| --- | --- |
| ファイルを生成したときは必ずパス名を出力して | 探す手間を消す |
| 文字起こしをするときは **mlx-whisper** を使って | Apple Silicon で約 30× 高速 |
| 大きめなタスクはチームエージェントをすぐに使って | 並列実行を促す |
| Web サイトを作ったら **Playwright MCP** で動作テストして | 完成宣言の前の検証 |

> 「とかその程度くらい」（薄井氏）

## CLAUDE.md に書くべきこと（推奨カテゴリ）

### 1. 立ち振る舞いルール
- 並列処理を使う／使わない
- 音声入力前提か
- 完成前に必ずやるべき検証（Playwright など）

### 2. 出力フォーマット
- ファイルを作ったらフルパスを明記する
- レポートの章立てを統一する
- 日付は YYYY-MM-DD で書く

### 3. プロジェクト場所のルール
- `~/dev-projects/<name>` に作る
- Desktop に作るのは明示指示があったとき

### 4. GitHub / デプロイ運用
- デフォルトのリポジトリ公開設定（public / private）
- 命名規則
- `.gitignore` に必ず入れるファイル

### 5. セキュリティ
- API キーは `.env` で扱う
- 機密データはコミットしない
- メールは送信せず下書きまで

## ユニーク事例 — 原始人プロンプト（Caveman Prompt）

<figure class="slide-figure">
  <img src="/slides/advanced/page-025.jpg" alt="原始人プロンプト">
  <figcaption>CLAUDE.md のユニーク事例：原始人プロンプト（p.25）</figcaption>
</figure>

海外で流行している **トークン節約 TIPS** です。

```text
[原始人プロンプト]
原始人として振る舞う。
単語ベースで話す。敬語禁止。単文完結。
ただし技術説明は省かない。
```

これを CLAUDE.md に入れると、Claude の出力が
**「了解。シンプルアラーム作る。フォルダはどこ？ GitHub push 進める」**
のような短文に切り替わります。

::: warning 副作用
読みづらくなるので、**本気でトークン節約したい人向け**。
講師の言葉では「Claude が "俺、人間殺す" みたいな喋り方になったら成功」。
:::

## CLAUDE.md のテンプレート

::: code-group
```markdown [推奨テンプレ]
# 立ち振る舞いルール

## プロジェクト場所
- 新規プロジェクトは `~/dev-projects/<name>/` に作る
- Desktop に作るのは明示指示があったときのみ

## 完成の定義
- Web アプリを作ったら **必ず Playwright MCP で動作確認** してから完成と言う
- 静的解析（型・lint）だけで完了扱いにしない

## 並列処理
- 大きいタスク・調査は **チームエージェント** を編成して並列で進める
- 1 ファイル参照・1 キーワード grep は対象外

## セキュリティ
- API キーはハードコードしない。`.env` を使い `.gitignore` に追加
- 公開デプロイ前に **必ず Supabase RLS を確認**
- メール MCP は **下書きまで**

## 出力フォーマット
- ファイル生成時は最後にフルパスを箇条書きで明示
- 日付は YYYY-MM-DD
- 完了報告は「変更点 1 行 + 次の一手 1 行」

## 音声入力
- ユーザは音声入力。誤字脱字は文脈で補正してから処理
```
:::

## CLAUDE.md デバッグの仕方

書いたルールが効いていないと感じたら：

```text
今、適用されている CLAUDE.md のルールを
箇条書きで全部列挙してください。
読まれていないものがあれば教えてください。
```

→ Claude が **実際に認識しているルールセット** を返してくれます。
